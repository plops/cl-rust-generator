Ich baue eine Remote-Desktop-Anwendung in Rust, die über eine extrem schmale Bandbreite (ca. 6 kB/s) Screenshots von einem X11-Server an einen Client übertragen soll.

Anforderungen:
1. Geringe Bandbreite & Latenz: 6 kB/s entspricht Modem-Geschwindigkeit. Ein Vollbild-Screenshot via AV1/AVIF ist dafür zu groß.
2. Bild/Text-Trennung: Ein neuronales Netz (ONNX-Inferenz auf CPU via ort / onnxruntime in Rust) soll auf dem Screenshot Bild-Bereiche (Fotos, Grafiken, Diagramme, Icons) und Text-Bereiche trennen.
3. Rekonstruktion:
   - Text-Regionen sollen ausgelesen und als Vektordaten (Bounding Box + UTF-8-String + Farbe) übertragen werden. Der Client rendert diese scharf mit einer Bitmap-Schriftart (GNU Unifont).
   - Echte Grafik-/Bild-Regionen sollen als Bounding Boxes ausgeschnitten, per AV1 Still-Picture (rav1e) stark komprimiert und als kleine Kacheln übertragen werden.
   - Einfache Hintergründe (Fensterflächen, Terminal-Hintergründe) sollen idealerweise gar nicht per AV1 übertragen werden, sondern nur als Farbwerte.

## Model Card
hier ist information von hugging face model card:


GPA-GUI-Detector

A YOLO-based GUI element detection model for detecting interactive UI elements (icons, buttons, etc.) on screen for GUI Process Automation. This model is finetuned from the OmniParser ecosystem.
Model

The model weight file is model.pt. It is a YOLO model trained with the Ultralytics framework.
Installation

pip install ultralytics

Usage
Basic Inference

from ultralytics import YOLO

model = YOLO("model.pt")
results = model("screenshot.png")

Detection with Custom Parameters

from ultralytics import YOLO
from PIL import Image

# Load the model
model = YOLO("model.pt")

# Run inference with custom confidence and image size
results = model.predict(
    source="screenshot.png",
    conf=0.05,        # confidence threshold
    imgsz=640,        # input image size
    iou=0.7,          # NMS IoU threshold
)

# Parse results
boxes = results[0].boxes.xyxy.cpu().numpy()   # bounding boxes in [x1, y1, x2, y2]
scores = results[0].boxes.conf.cpu().numpy()  # confidence scores

# Draw results on image
img = Image.open("screenshot.png")
for box, score in zip(boxes, scores):
    x1, y1, x2, y2 = box
    print(f"Detected UI element at [{x1:.0f}, {y1:.0f}, {x2:.0f}, {y2:.0f}] (conf: {score:.2f})")

# Or save the annotated image directly
results[0].save("result.png")

## ONNX Preparation

Why GPA-GUI-Detector Fits Your Rust Pipeline

    Lightweight & CPU-Ready: The model weights clock in at roughly ~40–44 MB. It was fine-tuned out of the heavy OmniParser ecosystem specifically to act as a lightweight, localized bounding-box predictor that bypasses cloud-VLM latency completely. 
    Hugging Face +3
    True Screen Focus: Unlike document or generic object datasets, this was trained on modern operating system screenshots (macOS/Linux/Windows desktop states). It isolates interactive buttons, application docks, text blocks, and graphical components with clean geometric accuracy. 
    Hugging Face +2

Converting it to a YOLOv26 ONNX Pipeline
Because Salesforce natively distributed the GPA-GUI-Detector weights as a standard PyTorch/Ultralytics .pt model checkpoint, you can easily ingest its trained features and repackage them into a lightning-fast, NMS-free YOLOv26 ONNX deployment block. 
Hugging Face +1
To convert these weights into a tight format for your Rust application:
python

from ultralytics import YOLO

# 1. Load the specialized Salesforce GUI Detector weights
# (Ultralytics handles pulling the checkpoint directly from HF)
base_gui_model = YOLO.from_pretrained("Salesforce/GPA-GUI-Detector")

# 2. Export to an end-to-end NMS-free ONNX file
# This optimizes it for 'ort' inside your Rust server loop
base_gui_model.export(
    format="onnx", 
    nms=False,        # Strips out sequential NMS code for 40%+ faster CPU loops
    simplify=True,    # Optimizes ONNX computational graphs
    imgsz=640         # Anchor dimension matching standard screenshot scaling
)

Use code with caution.
Running this Python snippet leaves you with a compact GPA-GUI-Detector.onnx file that runs in milliseconds on a standard CPU core. Inside your Rust server, you can map its class IDs directly to your network router: Text regions get peeled away for the Unifont vector layer, while non-homogenous Icon/Button/Graphic regions get processed by your rav1e AV1 encoder snippet.

vermeiden. sobald eine datei mehr als eine klar abgrenzbare
zustaendigkeit hat oder ca. 300 zeilen ueberschreitet, ist sie in
semantisch getrennte einzelne dateien zu unterteilen. jede neue datei
bekommt am anfang eine zweistellige nummer plus einen namen der
widerspiegelt was darinsteht, z.b. `01_clock.rs`, `02_usb_cdc.rs`,
`03_router.rs` in `firmware/src/` bzw. `01_types.rs`, `02_frame.rs` in
`common/src/`. regeln: aufsteigende nummern folgen der
initialisierungs-/datenfluss-reihenfolge (clock vor peripherie,
transport vor protokoll, protokoll vor modus), zusammengehoeriges
bleibt in einer datei (kein auseinanderreissen von zusammengehoerigen
typen + ihren tests), `mod.rs`/`lib.rs`/`main.rs` enthalten nur
modul-deklarationen und die oberste verdrahtung (init, spawn, join),
kein verhalten. aufteilung immer ohne verhaltens-aenderung
durchfuehren (vorher/nachher: alle tests plus smoke
gruens). bestehende dateien (`main.rs`, `text.rs`, `frame.rs`,
`router.rs`) bei bedarf nach diesen regeln umbauen, sobald du sie
anfasst.
