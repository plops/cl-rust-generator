## Vorschlaege fuer die Portierung

### 1. Rust vs. Kotlin: Keep Parts or Rewrite?

**Recommendation: Use a Hybrid Architecture (Rust Core + Kotlin UI).**

Here is why a 100% pure Kotlin reimplementation is problematic:

1. **AV1 Decoding is the primary bottleneck:**
   * There is **no mature, pure-Kotlin/Java AV1 software decoder**. 
   * On Android, while `MediaCodec` supports AV1 (API 29+), feeding it individual chunked still-picture OBUs per tile is notoriously brittle and adds buffer latency compared to `dav1d`/`rav1d`.
   * On Desktop JVM, you would need native C/Rust bindings (`dav1d` or FFmpeg) anyway.
2. **Protocol drift:**
   * The server and protocol types (`lbw-common`) are written in Rust. Sharing or binding the Rust types ensures you never have subtle serialization bugs, endianness mismatches, or YUV-to-RGBA conversion inaccuracies.
3. **Threading & Performance:**
   * Tile assembly, AV1 decoding, and pixel blitting onto a shared frame buffer run exceptionally well in native Rust without triggering JVM Garbage Collection pauses.

#### Dividing the Responsibilities

* **Keep in Rust:**
  * `02_av1.rs` (AV1 decoder).
  * `03_net.rs` & `lbw-common` (protocol framing, packet assembly, TCP handling, ACK pacing).
  * `04_scene.rs` (RGBA pixel buffer management; write directly into a direct `ByteBuffer` / native memory pointer shared with Kotlin).
* **Write in Kotlin:**
  * **UI & Rendering:** Use **Compose Multiplatform** (supports Android and Desktop JVM). Draw the scene bitmap and overlay the text strings using `Canvas`.
  * **Input handling:** Intercept touch/mouse/keyboard and convert to an enum/event passed into Rust.
  * **SSH Tunneling:** Either bind SSH inside Kotlin or connect through local port forwards.

### 3. Step-by-Step Porting Guide

#### Step A: Generating the Rust ↔ Kotlin Bridge (UniFFI)
Instead of hand-writing raw JNI C bindings, use [**UniFFI**](https://mozilla.github.io/uniffi-rs/) (developed by Mozilla) or `android-ndk` with `uniffi`. UniFFI generates type-safe Kotlin bindings (`.kt`) directly from your Rust code.

Define an interface in Rust:

```rust
// In your rust wrapper crate (e.g. lbw_core)
pub struct LbwEngine {
    // holds Net, Scene, Decoder
}

pub trait LbwCallback: Send + Sync {
    fn on_frame_ready(&self);
    fn on_text_updated(&self);
    fn on_disconnected(&self, reason: String);
}

impl LbwEngine {
    pub fn new(host: String, port: u16, cb: Box<dyn LbwCallback>) -> Self { ... }
    pub fn send_key(&self, keysym: u32, mods: u8) { ... }
    pub fn send_char(&self, ch: u32) { ... }
    pub fn send_mouse(&self, x: u16, y: u16) { ... }
    pub fn send_button(&self, button: u8, down: bool) { ... }
    pub fn copy_rgba_to(&self, target_buffer: &mut [u8]) { ... }
}
```

#### Step B: Scene Rendering in Kotlin (Jetpack Compose / Compose Multiplatform)
In Compose, you can blit the frame buffer onto a `Bitmap` and draw the texts cleanly in the UI pass:

```kotlin
@Composable
fun RemoteDesktopScreen(engine: LbwEngine, sceneState: SceneState) {
    var bitmap by remember { mutableStateOf<ImageBitmap?>(null) }
    
    // Canvas drawing
    Canvas(
        modifier = Modifier
            .fillMaxSize()
            .pointerInput(Unit) {
                detectTapGestures(
                    onPress = { offset ->
                        engine.sendMouse(offset.x.toInt(), offset.y.toInt())
                        engine.sendButton(1, true)
                        tryAwaitRelease()
                        engine.sendButton(1, false)
                    }
                )
            }
    ) {
        // 1. Draw rasterized video canvas
        bitmap?.let { drawImage(it) }

        // 2. Overlay server text items on top with crisp rendering
        for (item in sceneState.texts.values) {
            drawRect(
                color = Color(item.bg[0], item.bg[1], item.bg[2]),
                topLeft = Offset(item.rect.x.toFloat(), item.rect.y.toFloat()),
                size = Size(item.rect.w.toFloat(), item.rect.h.toFloat())
            )
            // Draw text via DrawScope.drawText or standard TextLayout
        }
    }
}
```

#### Step C: Input Mapping for Mobile & Desktop
In the original Rust client, Macroquad assumes keyboard and physical mouse:
* **Desktop (Kotlin):** Map Compose `KeyEvent` to `keysym` values (using `05_input.rs`'s table: `K::Enter -> 0xff0d`, etc.).
* **Mobile (Android Touch):** 
  * Direct taps often obscure small remote desktop UI elements. Implement a **trackpad mode** (relative mouse delta with a visible cursor) or **direct tap mode**.
  * Use a floating virtual key toolbar (for Ctrl, Alt, Esc, Tab, Arrow keys).

#### Step D: Text Selection and Clipboard (`06_select.rs`)
Because the server provides text boxes with coordinates (`TextItem`), you can implement native selection in Kotlin:
1. Collect all `TextItem`s intersecting your selection bounding box.
2. Sort them by vertical midpoint ($y + h/2$), then by $x$.
3. Join them into lines with `\n` and push to the Android/system clipboard:
   ```kotlin
   val clipboard = LocalClipboardManager.current
   clipboard.setText(AnnotatedString(selectedText))
   ```

### 4. Handling the SSH Tunnel in Kotlin

If you do not want the user to run an external terminal app (like Termux, ConnectBot, or OpenSSH), you can establish the SSH tunnel directly inside the Kotlin application before connecting `lbw-client`.

Using **Apache MINA SSHD** or **JSch**:

```kotlin
// Example using JSch for local port forwarding
import com.jcraft.jsch.JSch
import com.jcraft.jsch.Session

class SshTunnel(
    private val user: String,
    private val host: String,
    private val sshPort: Int = 22,
    private val remoteLbwPort: Int = 7878
) {
    private var session: Session? = null

    fun connect(privateKey: ByteArray?, password: String?): Int {
        val jsch = JSch()
        privateKey?.let { jsch.addIdentity("key", it, null, null) }
        
        session = jsch.getSession(user, host, sshPort).apply {
            password?.let { setPassword(it) }
            setConfig("StrictHostKeyChecking", "no")
            connect(10000)
            
            // Assign a local dynamic port (0 = pick any free port)
            // Forwards localhost:<assignedPort> -> server:remoteLbwPort
            val localAssignedPort = setPortForwardingL(0, "127.0.0.1", remoteLbwPort)
            return localAssignedPort
        }
        return -1
    }

    fun disconnect() {
        session?.disconnect()
    }
}
```

**Lifecycle Flow:**
1. App launches $\to$ user enters SSH credentials/key and server host.
2. Kotlin starts the SSH tunnel, binding remote port `7878` to local port `X`.
3. Kotlin starts the `LbwEngine` targeting `127.0.0.1:X`.
4. If the tunnel disconnects, Kotlin alerts the engine and attempts an exponential backoff reconnect.

## Vorschlaege zur Github Action

Here is a complete GitHub Actions workflow (`.github/workflows/build.yml`) to build the **hybrid Android application** (compiling the Rust native libraries for Android architectures with `cargo-ndk`, packaging them with Gradle, and uploading the generated APK as an artifact).

---

### `.github/workflows/build.yml`

```yaml
name: Build Android Client

on:
  push:
    branches: [ "main", "master" ]
  pull_request:
    branches: [ "main", "master" ]
  workflow_dispatch:

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          submodules: recursive

      # 1. Set up JDK for Gradle
      - name: Set up JDK 17
        uses: actions/setup-java@v4
        with:
          distribution: 'temurin'
          java-version: '17'
          cache: 'gradle'

      # 2. Set up Android NDK (Ubuntu runners have Android SDK pre-installed)
      - name: Set up Android NDK
        id: setup-ndk
        run: |
          # Pick the latest LTS NDK available on the GitHub runner
          NDK_PATH=$(ls -d $ANDROID_SDK_ROOT/ndk/* | sort -V | tail -n 1)
          echo "Using NDK at $NDK_PATH"
          echo "ANDROID_NDK_HOME=$NDK_PATH" >> $GITHUB_ENV
          echo "NDK_PATH=$NDK_PATH" >> $GITHUB_ENV

      # 3. Set up Rust toolchain and Android targets
      - name: Set up Rust
        uses: actions-rust-lang/setup-rust-toolchain@v1
        with:
          toolchain: stable
          targets: |
            aarch64-linux-android
            armv7-linux-androideabi
            x86_64-linux-android
            i686-linux-android
          cache-work-dir: rust-core

      # 4. Install cargo-ndk to handle cross-compilation & toolchain binding
      - name: Install cargo-ndk
        run: cargo install cargo-ndk

      # 5. Build Rust shared libraries directly into app's jniLibs directory
      - name: Build Rust core (.so)
        run: |
          mkdir -p androidApp/src/main/jniLibs
          cd rust-core
          cargo ndk \
            -t arm64-v8a \
            -t armeabi-v7a \
            -t x86_64 \
            -t x86 \
            -o ../androidApp/src/main/jniLibs \
            build --release

      # 6. Grant execute permission for gradlew
      - name: Grant execute permission for gradlew
        run: chmod +x gradlew

      # 7. Build Android APK (assembleDebug or assembleRelease)
      - name: Build with Gradle
        run: ./gradlew assembleDebug --stacktrace

      # 8. Upload the built APK as a GitHub Action artifact
      - name: Upload APK
        uses: actions/upload-artifact@v4
        with:
          name: lbw-client-debug.apk
          path: androidApp/build/outputs/apk/debug/*.apk
```

### Key Details in This Setup

1. **`cargo-ndk` Output Flag (`-o`)**:
   Running `cargo ndk ... -o ../androidApp/src/main/jniLibs build --release` automatically maps the target Rust architecture folders to the ABI names expected by Android:
   * `aarch64-linux-android` $\rightarrow$ `jniLibs/arm64-v8a/liblbw_core.so`
   * `x86_64-linux-android` $\rightarrow$ `jniLibs/x86_64/liblbw_core.so`
   * `armv7-linux-androideabi` $\rightarrow$ `jniLibs/armeabi-v7a/liblbw_core.so`

2. **Android NDK Detection**:
   GitHub's standard `ubuntu-latest` runner comes with the Android SDK and multiple NDK versions pre-installed under `$ANDROID_SDK_ROOT/ndk/`. Step 2 detects the latest one and sets `ANDROID_NDK_HOME`, which `cargo-ndk` uses to find the cross-compiler toolchains.

3. **Caches**:
   * `actions/setup-java` caches Gradle dependencies automatically.
   * `actions-rust-lang/setup-rust-toolchain` caches `~/.cargo` and build targets.

4. **Release Builds**:
   If building for production release instead of debug, replace `./gradlew assembleDebug` with `./gradlew assembleRelease` and configure signing credentials via GitHub Secrets (`SIGNING_KEY`, `KEY_ALIAS`, `KEY_PASSWORD`).
